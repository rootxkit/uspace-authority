`internal/picture`, `schemas/picture/*` (only the authority-specific

## What to build

- `GET /v1/picture/ws`: WebSocket (`coder/websocket`) authenticated by
  the `uspace_session` cookie on a same-origin upgrade with an `Origin`
  allow-list (`PICTURE_ALLOWED_ORIGINS`), verified by the shared
  `core/auth.Verifier` (M22; no ticket route, nothing in a query
  string); a failed check closes with 4401 and the console re-logs in.
  Every frame in both directions is the common console frame (M29):
  the `04 §2` envelope (`schema`, `msg_id`, `producer` =
  `authority/picture-ws`, `ts`, `rx_ts`, `captured_at`, `time_source`,
  `backlog`) plus a `body` named by `schema`.
  - Client → server: `console/subscribe/v1 {bbox, layers[]}`; the
    server subscribes to `trk.v1.<cell3>.<cell5>.>` and `man.v1...`
    for the cells intersecting the bbox plus a margin, resubscribing
    on change (bounded number of cells per client, E-10).
  - Server → client on connect and on every re-subscribe:
    `console/status/v1` then `console/snapshot/v1` (`tracks[]`,
    `alerts[]` = active violations replayed, C-08, `manned[]`,
    `zones_version`).
  - Server → client live: `track/telemetry/v1` (the `04 §3.1` fields,
    plus `age_s` computed server-side and `source_state`),
    `track/manned/v1`, `violation/v1` (raise and clear),
    `source/status/v1` (every `src.v1` change: enabled, disabled by
    whom, stale, lagging), and `console/status/v1` every 2 s with
    `connection_id`, `server_ts`, `policy_version`, `stale_after_s`,
    `live_max_age_s`, `dropped_frames`, `degraded[]`, `sources[]` and
    this system's extras `projection_age_s`, `cis_version`,
    `cis_age_s`, `dp_state`, `nats`. The extras are the only thing
    `schemas/picture/` defines; thresholds come from `authority_policy`
    in this frame, never from the kit (INV-03).
- Throttle: per client, per track, ≤ 2 Hz when the viewport holds more
  than 200 tracks, else every message; dropped frames counted per
  client and reported in `console/status/v1` (`05 §5`).
- Track state cache per cell (last message per track id, aged out at
  `stale_after_s`, bounded) so a connecting client gets a snapshot
  before the live stream; `GET /v1/picture/snapshot?bbox=` serves the
  same snapshot over HTTP.
- `GET /v1/picture/sources`: every source instance with its last
  `src.v1` status, the projection ages and the CIS age.
- Degradation: NATS down → the client receives a `console/status/v1`
  with `nats: unavailable since T` in `degraded[]` within 5 s and the
  last snapshot stays marked stale; nothing is removed silently (E-02
  test: kill NATS, read the frame).
- No PII: the frame type has no name, address or contact field; the
  remote pilot / operator position from a DP flight is included only for
  the console realm and omitted for any public subset (none is built
  here; the omission is a field-level rule tested now).

## Tests

- Unit: viewport → cell set; throttle at 199, 200 and 201 tracks (E-01
  pair); snapshot ageing; every frame validated against the lab's
  common schemas plus this repo's extras; an upgrade without the
  cookie, with a wrong `Origin`, and with a machine token in place of a
  session, each refused beside the accepted one (E-01).
- Integration: two clients with overlapping viewports receive the same
  track once each; a violation raised before connect is replayed; a
  source disabled appears as `disabled by <who>` within one status
  interval; NATS outage frame; `dropped_frames` rises under a 5000
  msg/s synthetic flood and the client stays connected.
- Load smoke: 10 consoles × 200 tracks at 1 Hz for 60 s; CPU and
  frames/s in the PR (`05 §1`: 2000 msg/s out at 100 drones).
