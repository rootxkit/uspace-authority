## What to build

- `GET /v1/picture/ws?bbox=`: session-authenticated WebSocket
  (`coder/websocket`); the client sends `{viewport: bbox}` messages;
  the server subscribes to `trk.v1.<cell3>.<cell5>.>` and
  `man.v1...` for the cells intersecting the viewport plus a margin,
  resubscribing on viewport change (bounded number of cells per client,
  E-10), and sends frames: `track` (the `04 §3.1` fields minus anything
  that is not in the picture contract, plus `age_s` computed server-side
  and `source_state`), `violation` (active ones, replayed on connect and
  on viewport change, C-08), `source` (every `src.v1` change: enabled,
  disabled by whom, stale, lagging), `status` (`projection_age_s`,
  `cis_age_s`, `dp_state`, `dropped_frames`, degraded inputs). Every
  frame type has a schema in `schemas/picture/`.
- Throttle: per client, per track, ≤ 2 Hz when the viewport holds more
  than 200 tracks, else every message; dropped frames counted per
  client and reported in `status` (`05 §5`).
- Track state cache per cell (last message per track id, aged out at
  `stale_after_s`, bounded) so a connecting client gets a snapshot
  before the live stream; `GET /v1/picture/snapshot?bbox=` serves the
  same snapshot over HTTP.
- `GET /v1/picture/sources`: every source instance with its last
  `src.v1` status, the projection ages and the CIS age.
- Degradation: NATS down → the client receives a `status` frame with
  `bus: unavailable since T` within 5 s and the last snapshot stays
  marked stale; nothing is removed silently (E-02 test: kill NATS, read
  the frame).
- No PII: the frame type has no name, address or contact field; the
  remote pilot / operator position from a DP flight is included only for
  the console realm and omitted for any public subset (none is built
  here; the omission is a field-level rule tested now).

## Tests

- Unit: viewport → cell set; throttle at 199, 200 and 201 tracks (E-01
  pair); snapshot ageing; frame schemas validated.
- Integration: two clients with overlapping viewports receive the same
  track once each; a violation raised before connect is replayed; a
  source disabled appears as `disabled by <who>` within one status
  interval; NATS outage frame; `dropped_frames` rises under a 5000
  msg/s synthetic flood and the client stays connected.
- Load smoke: 10 consoles × 200 tracks at 1 Hz for 60 s; CPU and
  frames/s in the PR (`05 §1`: 2000 msg/s out at 100 drones).
