# WP-23: web: oversight, occurrences, sources, audit, police and public pages

Branch `feat/WP-23-web-oversight`. Milestone A-M5. Owns the `web/`
pages for violations, incidents and evidence, occurrences (officer
realm), sources, audit and the DPO report, the police realm, and the
public pages (registration check, public register, rules). Depends on
WP-21, WP-17, WP-18, WP-19 (and WP-12, WP-10, WP-20 APIs). Consumers:
A-M5.

## Read first

1. `docs/PLAN.md` §5 violation, incident, occurrence, police, source,
   audit rows; §7 (what each realm may see).
2. Spec `01 §1` users (the `inspector` never sees reporter identities;
   police realm separate), `02 F10`, `06 §2` T6, `06 §5`.
3. The runbooks of WP-12 (violations), WP-17 (incidents, hole labels),
   WP-18 (occurrences), WP-19 (police), WP-10 (source control).
4. LESSONS B-11 (disabled is not silent), B-13 (holes as holes, alerts
   "unavailable" not "none"), C-12 (no wording that claims a loss that
   has not happened), R-05, E-02.

## What to build

- Violations: list with filters, detail with the evidence excerpt on a
  map (segments cut by holes, each labelled; nothing interpolated),
  numbers with their units and datums, the terrain dataset and spacing
  beside every AGL figure with the Copernicus attribution, the
  `evidence_trust: broadcast` warning, review actions (reviewed,
  dismissed, escalated with note).
- Incidents: case file, aircraft, notes, evidence pack creation
  (`oversight` or `legal` with purpose and case reference), manifest
  view, hash shown, download, verify.
- Occurrences (`incident_officer` only; the navigation entry does not
  exist for other roles, and the API refuses anyway): intake queue with
  the 72 h flag, detail with the reporter block rendered only when the
  API returns it, classification and analysis forms, export with a
  warning that free-text narrative is exported as written.
- Sources: every instance with `enabled`, `disabled by <who> (reason)`,
  `healthy`, `stale`, `lagging (lag_s)`, `never heard`, counters;
  enable/disable with a mandatory reason (admin).
- Audit: event search, the monthly chain verification result, the DPO
  report.
- Police realm: a separate layout (no console navigation), the purpose
  and case-reference fields on every query, the aircraft/operator/serial
  queries, exports; a different colour band so an officer always knows
  which realm they are in.
- Public pages (no session): registration check, the public certificate
  register, the rules page (configurable Markdown), `ka`/`en`.

## Tests

- Playwright against the stub API: a violation with a hole renders the
  hole label; an `inspector` cannot reach the occurrence routes and an
  `incident_officer` can (E-01); a police query without a purpose is
  blocked client-side and, with the client check removed in the test,
  refused by the stub as the API would; the public check returns
  status only.
