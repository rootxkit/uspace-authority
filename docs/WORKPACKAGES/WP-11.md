## What to build

- `ground.Service` built from config: `GROUND_DIR` (tiles and
  `index.json` in the lab's PGM container), `GEOID_FILE` (EGM2008 2.5′
  PGM), tile cache size, retry interval. Both optional: with neither,
  the service reports `terrain: not configured`, `geoid: not configured`
  and every caller behaves per D-04/R-07 (not evaluated; nil AMSL).
- `Env(p core.LatLon) zones.Env`: `GroundKnown` with `GroundM` from
  `terrain.Store.Elevation`, `GroundUnknown` when the store answers nil
  (outside the index, nodata, unreadable tile: counted, retried once per
  `RetryAfter`, D-04), `GroundNotConfigured` without a store;
  `UndulationM` from the geoid or nil. Terrain reads go through core's
  bounded LRU and never hold a lock across a tile read (B-06).
- `Undulator` for WP-8 and `Ground` for WP-12 as the core interfaces.
- `Daylight` implementation for `ed318.Applies` (sunrise, sunset, and
  civil twilight for BMCT/EECT) from position and date with the
  NOAA-style algorithm, written from the cited formula with a test
  against published almanac values for Tbilisi on two dates (never from
  memory; cite the source in the doc comment).
- Status: at startup and on every status line, which datasets are
  loaded (`Attribution` of core shown wherever an AGL number is shown,
  D-05), tile cache hits/misses/unknown/unreadable, geoid description;
  `ground.Problems()` listing what cannot be judged, for WP-12's
  error-level line when a PROHIBITED zone needs what is missing (Z-09).
- `deploy/fetch-ground.sh`: fetches the Copernicus GLO-30 cells for a
  configured list (Georgia's 1° cells) and the geoid grid into the
  volume using the lab's conversion tooling (the PGM writer lives in the
  lab; this script calls it or downloads the lab's published tiles),
  verifying checksums; nothing large is committed.

  interval (D-04).
