# WP-18: occurrence reporting (Reg. 376/2014)

Branch `feat/WP-18-occurrences`. Milestone A-M3. Owns
`internal/occurrences`, the PostgreSQL schema `occurrences` with its own
role, `schemas/occurrence/v1.json` (**owned here**: it is the request
body of this API, so by the ownership rule the authority publishes it
with examples and the USSP and ANSP consume it from this repo, M14),
the routes `/v1/occurrences/*`. Depends on WP-2 (scope
`occurrences.write`, role `incident_officer`). Consumers: WP-23;
ussp WP-15 and ansp WP-10 (as senders).

Reviewed adversarially: the segregation from enforcement is a legal
requirement (376 Art. 15–16), and the test that proves it is the point.

## What to build

- Schema `occurrences` with role `authority_occurrences`; the main
  application role has **no** grant on it; `api` opens a second pool
  with that role used only by this package (a layout test greps that no
  other package imports `internal/occurrences`'s store).
- `occurrence_reports`: `report_ref`, `channel` mandatory/voluntary,
  `reporter_org`, `reporter_person_enc` (`reporter.person_ref` arrives
  from the sender as an opaque reference in clear text over TLS, M13:
  there is no public-key exchange and no sender-side encryption; this
  system encrypts it at rest with a key separate from the PII key,
  `OCCURRENCE_KEY`, and decrypts only for `incident_officer` reads, each
  audited), `occurred_at`,
  `became_aware_at`, `received_at`, `within_72h` (computed, never
  edited), `category`, `aircraft[]` (serial, operator registration
  public part, flight id, authorisation number), `manned[]`,
  `intent_refs[]`, `min_separation`, `narrative`, `evidence_urls[]`,
  `risk_classification`, `analysis`, `follow_up`, `state`
  received/classified/analysed/closed; `deidentified_exports(id,
  created_at, content_hash, format)`.
- Intake `POST /v1/occurrences` (`occurrence/v1`): from USSPs and the
  ANSP with scope `occurrences.write` (the `sub` recorded as
  `reporter_org`), from operators through the portal session (WP-20) or
  a signed public form later; idempotent on `(reporter_org,
  report_ref)`; acknowledgement returns the authority's id; late (> 72 h)
  reports accepted and flagged, never refused.
- Officer routes: list, get (reporter identity only for
  `incident_officer`, audited `pii_view`), `PATCH .../analysis`,
  `POST .../classify` (376 Art. 7(2); the scheme is a configured list),
  `POST /v1/occurrences/export` producing a de-identified record set
  (no reporter, no names, no addresses; aircraft by serial and
  registration public part) in a JSON layout tagged
  `format: eccairs-compatible-draft` with the field mapping documented
  (Q-A12), hash-sealed and audited.
- Segregation: no foreign key, view, or query from `occurrences.*` to
  `public.violations` or back; `internal/violations` and
  `internal/incidents` never import this package; an incident may hold
  a free-text reference to an occurrence id typed by an officer, and
  the reverse is not allowed (test: the incident schema has no
  `occurrence_id` column; the occurrence schema has no `violation_id`
  or `incident_id` column; `pg_depend` shows no cross-schema
  dependency).
- Operators' reports under 947 Art. 19(2) count as mandatory channel
  with `reporter_org = operator:<registration public part>`.

## Tests

- Unit: `within_72h` at the boundary (E-01 both sides); export
  redaction (a reporter name planted in every free-text field is absent
  from the export only where the field is structured — narrative is
  exported as written and the test documents that the officer redacts
  it; the UI (WP-23) warns); idempotent intake.
- Integration: a report posted by the fake USSP client; `inspector`
  reading it gets no reporter identity (403 on the identity field) and
  `incident_officer` does (audited); the segregation test above against
  the live catalog; export hash recorded.
- E-10: attachment URL list bounded; narrative length bounded.
