## What to build

- Import: `POST /v1/registry/import` (registrar) accepting a CSV or JSON
  export of uas.gov.ge with a **rules file** (column mapping, status
  mapping, date formats, the registration-number pattern) supplied as
  configuration, never committed with real data; dry-run mode returning
  every problem by row and field (all or nothing, as zones); idempotent
  on the source id; rows marked `source = uas_gov_ge_import`; a
  periodic re-import job when `REGISTRY_IMPORT_URL` is configured
  (agreed access only, G-11); every import an `events` row with counts.
- Public `GET /v1/registry/check?number=` → `valid` / `suspended` /
  `revoked` / `unknown` and `valid_until` only; rate-limited per IP;
  response schema PII-free (the grep test of WP-3 extended).
- Applications (feature-flagged): `POST /v1/registry/applications`
  with the Art. 14(2) fields (encrypted at rest), email verification by
  a signed link (no account), `GET .../{id}` by a signed token;
  registrar review (`approve` creates the operator and issues the
  registration number through WP-3; `refuse` with a reason); every step
  audited; applications purged after a configured period.
- Registration number issuance (when the authority is the record):
  `regnum` pattern from policy, the secret part generated and shown
  once in the approval message, stored hashed (Q-A10).
- Operator occurrence intake: `POST /v1/occurrences` from a verified
  operator email link (WP-18's intake with `reporter_org =
  operator:<public part>`).

## Tests

- Unit: rules-file mapping with every problem beside its acceptance;
  dry run changes nothing (E-02: read the dry-run report); number
  issuance matches the pattern and never repeats.
- Integration: an import of a synthetic `GEO-TEST-*` file; re-import
  idempotent; an application approved end to end with the flag on and
  refused with 404 with the flag off (E-01).
- E-10: import file size and row count bounded; application rate per
  IP bounded.
