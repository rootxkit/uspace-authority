# WP-25: the scenario harness

Branch `feat/WP-25-scenario-harness`. Milestone A-M2. Owns
`internal/ltest` (fixtures, simulators and the scenario runner) and the
CI job `scenarios`. Depends on WP-9, WP-10; the scenarios themselves are
written by the WPs that own the behaviour (WP-7, WP-8, WP-12, WP-14,
WP-15) using this harness. Consumers: every later WP; the lab's
`uss_qualifier` and `make demo` use the same doubles' contracts.

## What to build

- Fixtures: start PostGIS, TimescaleDB and NATS (service containers in
  CI; `testcontainers-go` or the dev compose locally), apply both
  migration trees, provision the bus, seed a policy, a registry
  (`GEO-TEST-*` operators, `TEST*` serials) and zones from a scenario
  file; run any subset of the processes in-process (each `cmd` exposes
  a `Run(ctx, cfg)` for this) with a controllable clock where the
  component allows one.
- Simulated receiver: takes aircraft paths (lat, lon, AMSL, speed,
  track, status) at 1 Hz, encodes ODID Basic ID, Location, System and
  Operator ID through `odid.Encode` (HAE = AMSL + N from the test geoid,
  R-16), signs batches with a run-time key, posts them to `rid-ingest`
  with configurable drop rate, latency, backlog, and address or serial
  changes (SC-10, SC-11).
- Fake F3411 SP and DSS: serve `GET /uss/flights?view=` and details
  from the same paths with `uas_standards` field names, create ISAs in
  the fake DSS, deliver ISA notifications, and simulate 413, slowness
  and outage (WP-14's scenarios).
- Fake CISP: `02 F1`/`F3` exactly (publications with `If-Match`,
  `ETag`, `/v1/changes`, signed webhooks) for WP-6.
- Fake ANSP: streams a recorded ADS-B file as `manned_track.v1` with
  outage control.
- Scenario runner: a scenario is a Go test that declares aircraft,
  receivers, zones and expected events; the runner collects `trk.v1`,
  `alrt.v1`, `events` rows and status lines and asserts the expected
  raises and clears **and** that nothing unexpected was raised (the
  missed-alert count and the false-alert count both zero), the alert
  latency distribution (`captured_at` → raise), and the no-silent-loss
  identity: accepted + refused + dropped = sent for every source.
  Results are written as JSON with the commit of this repo and of
  `uspace-core` (E-05).
- Production safety: `internal/ltest` is imported by `_test.go` files
  only (depguard); the simulated receiver sets `trust: simulated`
  nowhere on the wire (it is a real ODID broadcast as far as ingest
  knows) but its batches carry a `X-Lab-Scenario` header that production
  config refuses (`LAB_HEADERS_ALLOWED=false` default) so a stray
  simulator cannot reach staging (T11).
- CI job `scenarios`: runs on Go changes with the service containers,
  uploads the JSON results.

## Tests

- The harness tests itself: the simulated receiver's frames decode to
  the paths it was given (`odid.Decode` round trip); the fake SP's
  responses unmarshal through `f3411`; a scenario with a deliberately
  wrong expectation fails (E-01: prove the runner can detect a miss).
