# WP-14: the F3411 Display Provider

Branch `feat/WP-14-display-provider`. Milestone A-M4. Owns
`cmd/dp-poller`, `internal/dp`, the `ussp_flights` hypertable
(policies via WP-9's helper), the inbound route
`POST /uss/identification_service_areas/{id}`, the admin routes
`/v1/dp/*`, the conformance hook `GET /v1/dp/observations` (Q-A7) and
`api/clients/dss-rid.yaml`. Depends on WP-2 (tokens), WP-8 (track
format and the identification step), WP-9, WP-16 (USSP base URLs and
operating status). Consumers: WP-13, WP-12 (provider tracks are judged
like any other), WP-19, WP-26.

Safety-relevant (a wrong DP is a wrong picture of every USSP flight).
Reviewed adversarially.

## What to build

- Views: the set of areas to display = configured oversight areas
  (`POST /v1/dp/views`, admin, persisted) ∪ the console viewports that
  `picture-ws` reports (KV `dp_views`, bounded, with a TTL so an idle
  console stops polling). Each view is split into tiles with diagonal ≤
  `NetMaxDisplayAreaDiagonalKm` (7); a 413 from an SP splits the tile
  into four, at most three times (R-14).
- Discovery: per tile, `GET /rid/v2/dss/identification_service_areas?
  area=` (ecosystem token, audience `dss`, scope `rid.display_provider`)
  and a DSS subscription per tile (`PUT /rid/v2/dss/subscriptions/{id}`,
  ≤ 24 h, renewed at 75 %, ≤ `NetDSSMaxSubscriptionPerArea`); ISA
  notifications arrive at `POST /uss/identification_service_areas/{id}`
  (verified: token from the configured issuer with the DSS audience,
  body per `uas_standards`); the set of SPs to poll comes **only** from
  the ISAs' `uss_base_url` (never a configured USSP address, `00 §7`),
  cross-checked against the certificate register (WP-16): an SP whose
  base URL matches no operating certificate is still polled and shown
  with `provider_unknown: true` (nothing hidden) and counted.
- Polling: one poller per (SP, tile), 1 Hz (`dp_poll_hz`), one in-flight
  request per view, 5 s deadline keeping what arrived, body cap 1 MiB,
  ≤ 500 flights per response, ≤ 64 tiles per SP, ≤ 20 details fetches
  per poll (4 at a time) and only for tiles ≤ 2 km diagonal; an SP
  slower than p99 3 s is marked `slow` and polled at 0.5 Hz with age
  shown; an SP failing for 10 s is `unavailable since T` on the picture
  (never removed); every limit has a counter and one log line per
  minute (R-14). Plain HTTP refused except to localhost.
- Mapping: `RIDFlight` → `track/telemetry/v1`: `trust: provider`,
  `source: network_rid`, `source_instance: <uss id>`, `track_id =
  rid.AircraftID(serial)` when `uas_id.serial_number` is a CTA serial
  (I-05; otherwise `UnidentifiedID` of the F3411 flight id); altitude
  HAE → AMSL via the geoid; pressure altitude kept; `height` with its
  reference; speed/track/vertical special values → nil; `captured_at`
  from `timeplace.PlaceNetwork(state.timestamp, response timestamp,
  rx)` with `shown=false` states not published (older than 60 s);
  `backlog: false`; identification from `identify.ResolveBroadcast
  (serial, operator_id)` with `basis: as_broadcast` (Q-A8); the operator
  location kept on the row but marked PII-class for WP-13's rule. A
  state identical to the last published for the flight is not
  republished (R-14). A flight in two tiles is one flight.
- `ussp_flights` rows (`RIDFlight` and details as received, `ussp_id`,
  `isa_id`, `rx_ts`) to the writer; retention 24 h policy plus the
  hourly `older_than_24h` check (fails loudly, counted, on the status
  line).
- Availability arbitration: `PUT /v1/dp/providers/{uss_id}/availability`
  (admin, audited) → `PUT /dss/v1/uss_availability/{uss_id}` with scope
  `utm.availability_arbitration` (F3548 client types from core).
- Conformance hook (Q-A7): `GET /v1/dp/observations?view=` returning
  what the InterUSS `uss_qualifier` network RID observation interface
  expects, behind scope `dp.observe`; the exact shape is read from the
  qualifier at the lab's pinned commit and recorded in `SOURCE` (never
  from memory).
- Source control: `network_rid` type and per-USSP instance through the
  WP-10 follower: a disabled provider stops polling at once (SC-16) and
  its tracks age out as `source_disabled`.
- `src.v1.network_rid.<uss_id>` status every 2 s: ISAs, tiles, polls,
  flights, p95/p99 response time, state.

  known ISAs used until `time_end`, `dss_unavailable` shown; the 24 h
  check on a backdated row.
