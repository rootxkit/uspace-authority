# WP-21: web foundation and the inspector map

Branch `feat/WP-21-web-foundation`. Milestone A-M5. Owns `web/` (app
shell, BFF routes, i18n, generated API types, the inspector map page),
the CI job `web`, and the web Docker image. Depends on WP-13
(`picture-ws` contract) and on `uspace-ui` **≥ 0.2.0** on npmjs (the
`live` client and `TrackLayer` ship in 0.2.0; M33; exact pin, never a
git tag, M32). Consumers: WP-22, WP-23, WP-24.

## What to build

- Next.js App Router, TypeScript strict, Tailwind + shadcn/ui through
  `uspace-ui`'s theme; `pnpm` with `packageManager` pinned and
  `--frozen-lockfile` (M34); types through the kit's `uspace-ui-gen-api`
  from `../api/openapi.yaml` into `web/src/api/` (committed, verified
  in CI); the picture feed through the kit's `live` client
  (`useFeed`), which parses the common console frame; this repo's
  `console/status/v1` extras typed from `schemas/picture/*` via
  `json-schema-to-typescript` (committed, verified).
- BFF under `/_bff/*` (the kit's `bffHandlers`, three routes: login,
  logout, session): login and MFA forms post to `api` server-side, the
  session JWT is set as the `uspace_session` cookie (`HttpOnly`,
  `Secure`, `SameSite=Strict`), forwarded as a bearer by a single fetch
  wrapper; CSRF through `uspace_csrf` + `X-CSRF-Token` on every mutating
  form (M21); logout clears; no token in browser code. The WebSocket
  connects same-origin to `/v1/picture/ws` and the browser sends the
  cookie on the upgrade; there is no ticket route and nothing in a
  query string (M22); a 4401 close means "re-login". The kit's
  `sessionClaimsUnverified` reads `sub`, `exp`, `roles[]`, `realm` for
  display only (M20). CSP from the kit (`connect-src 'self'`, `font-src
  'self'`, `worker-src blob:`), fonts via `next/font/local`, basemap at
  `/basemap/` served by the deployment's Caddy (M38). No database, NATS,
  geometry or JWT library in `web/` (ESLint `no-restricted-imports` for
  `turf`, `h3`, `proj4`, `jose`, `pg`, `nats`; a CI grep as backstop).
- i18n: `ka` and `en` message catalogues from day one, every string
  through the catalogue (a lint rule flags string literals in JSX
  outside the catalogue); branding (name, logo, contact) from
  environment at build time.
- Pages in this WP: login/MFA, the app shell with navigation per role,
  and the **inspector map**: MapLibre from `uspace-ui` with the zone and
  track symbology, viewport-driven `/v1/picture/ws` subscription,
  tracks with trust class, identification status (with "as broadcast
  and unverified" for every broadcast and provider track), age, source
  state panel (enabled / disabled by whom / stale / lagging / never
  heard), active violations panel from `console/snapshot/v1` on
  connect, `console/status/v1`'s `degraded[]` shown as a banner (`nats
  unavailable since T`, `projection stale`, `cis stale`, `dp
  unavailable`), `dropped_frames` visible, thresholds (`stale_after_s`,
  `live_max_age_s`) taken from the frame and never defaulted in the
  browser (INV-03).
- Accessibility baseline (keyboard navigation, contrast from the kit),
  Georgian font rendering checked in a Playwright screenshot test.
- Dockerfile for `web` (built in CI; `next build` never on the server),
  `output: standalone`.

## Tests

- `tsc --noEmit`, ESLint strict with the restricted-import rules (a
  test fixture that imports `turf` must fail lint, E-01), generated
  types up to date.
- Playwright smoke against a stub API and a stub picture WS (serving
  the lab's `console/*` examples): login → map → tracks appear → a
  `console/status/v1` with `nats` in `degraded[]` shows the banner and
  the tracks stay with age (E-02); a 4401 close returns to login; the
  Georgian catalogue renders; no request leaves the origin (CSP
  report test).
